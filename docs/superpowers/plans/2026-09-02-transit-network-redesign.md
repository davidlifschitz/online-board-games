# TrainGames Transit Network Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the TrainGames product shell with the approved NYC-subway-inspired Transit Network interface while preserving all existing game, auth, voting, submission, V1/V2, and offline behavior.

**Architecture:** Keep the static HTML/CSS/JavaScript architecture and existing backend interfaces. Introduce the transit identity through shared `styles.css`/`navigation.css`, an SVG system map on the homepage, station/departure markup generated by `play.js`, and page-specific semantic presentation for Build and Leaderboard without changing their JS hooks.

**Tech Stack:** Static HTML/CSS/JavaScript, Node 22 contract tests, existing Supabase client integration, existing Vercel static hosting.

**Spec:** `docs/superpowers/specs/2026-09-02-transit-network-redesign.md`

## Global Constraints

- Preserve `/`, `/play.html`, `/build.html`, and `/leaderboard.html` URLs.
- Do not change Supabase schema, auth providers, vote semantics, or submission semantics.
- Do not change individual game engines, V1/V2 game routes, or service-worker cache namespaces.
- Use NYC subway route colors: `#0062CF`, `#D82233`, `#009952`, `#9A38A1`, `#EB6800`, `#F6BC26`.
- Do not append written color names to category labels.
- Mobile SVG network map must be horizontally pannable.
- Keep accessible focus treatment and reduced-motion handling.
